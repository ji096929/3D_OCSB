# 弱标注支持集痛点摸底（零训练，val_560）

日期：2026-11-16
范围：10 个新类别 × 56 eps = 560 任务（部分任务支持集无该类真值前景，实际有效数见下）
约束：冻结 COSeg，仅 S → Q，不引入任何外部池 U，不改动现有核心脚本。

---

## 0. 结论

1. **弱标注确实掉分，但幅度温和**：`Tight-Box` −0.86pp、`Rough-Box` −2.08pp、`3-Click` −1.89pp、`1-Click` −2.42pp（Arith）；Cumul 分别为 −0.64 / −2.04 / −2.22 / −2.05。
2. **最关键的证据是 `1-Click`**：支持集只剩 **1 个前景点**（信息量下降 99% 以上），只掉 2.4pp。这说明 **COSeg 的前景原型对支持集掩码精度极不敏感**——`getMutiplePrototypes` 的 FPS + 特征聚类本身就把少数种子点扩展成了覆盖整类的原型。
3. **盒内污染率与掉分无关**，甚至反向：bookshelf 污染率最高（0.285 / 0.380）却几乎不掉分（+0.17 / +0.34）；floor 污染率最低（0.093 / 0.177）却掉 1.3–2.3pp。
4. **朴素同源清洗恢复一半以上**：`Rough-Box` 从 −2.08pp 恢复到 −0.64pp（恢复 1.44pp），`Tight-Box` 从 −0.86 恢复到 −0.34。
5. **判断：弱标注本身不足以支撑一个新方向。** 痛点真实存在，但强度只有 1–2pp，且用"盒外背景特征参照 + 剔除高相似点"这种零训练手段就能恢复大半。把它做成主贡献，需要更强的证据。

---

## 1. 实验设置

### 1.1 四种弱标注掩码（均由支持集真实标签自动生成）

| 变体 | 构造方式 |
|---|---|
| `full` | 逐点真值掩码（原生 COSeg 上界） |
| `tight` | 真实前景点 AABB，盒内全部点视为前景 |
| `rough` | AABB 六面各外扩 5 cm，盒内全部点视为前景 |
| `3click` | 真实前景点 FPS 取 3 个，其余点全部算背景 |
| `1click` | 距真实前景质心最近的 1 个点 |

**关于 3-Click / 1-Click 的口径**：COSeg 的接口只有二值掩码、没有 ignore 通道，所以"点了 N 个前景点"在实现上等价于"这 N 个点标前景、其余全部标背景"。这也符合真实弱标注的形态——前景点昂贵、背景自动获得。原型构造时采用**有放回补齐**到 100 个（3 个点各重复 33 次、1 个点重复 100 次），避免原生"点数不足补零"引入大量零向量。

### 1.2 朴素同源清洗

以**盒外点特征均值**为背景参照（盒外前景漏出率为 0，见 2 节），计算盒内每点与参照的余弦相似度，剔除相似度高于盒内 `q` 分位的点后再建原型：

```
p_bg_ref = mean(z_i, i ∉ box)
sim_i    = cos(z_i, p_bg_ref)
mask_clean = box ∧ (sim_i ≤ quantile(sim_box, q))
```

`q ∈ {0.5, 0.7}`。

**清洗对 `Rough-Box` 更有效**（恢复 1.4pp vs tight 的 0.35pp），因为 rough 的污染点更多、且这些点多在边界附近，与盒外背景特征更接近，更容易被相似度筛掉。

**逐类看，清洗的收益并不均匀**：counter 从 rough 的 0.2012 提到 0.2387（+3.75pp），chair 则从 0.3267 掉到 0.3818 但仍是负收益。清洗会误删一部分真实前景（尤其当目标物体本身与周围背景同色同材质时）。

## 5. 判断

### 5.1 痛点真实性：存在，但强度不足以支撑独立方向

| 证据 | 含义 |
|---|---|
| 1-Click 只掉 2.4pp（信息量 −99%） | **支持集掩码精度不是瓶颈** |
| 掉分集中在 chair / desk 两类 | 不是普遍的弱标注问题，是特定形态的边界污染 |
| 4/10 类的 box 变体不掉分甚至为正 | 弱标注的负面效应在多数类上被噪声淹没 |
| 污染率与掉分不相关 | 不能用"标注越粗掉得越多"来讲故事 |
| 零训练清洗恢复一半 | 剩下的痛点只有 0.5–0.6pp |

如果把它写成一个方法贡献，审稿人会问："你的方法解决了 1.4pp 的问题，而这 1.4pp 用一行相似度过滤就能拿回 1.4pp"。

### 5.2 值得保留的部分

1. **`1-Click` 的结果本身是个有价值的发现**：COSeg 的原型机制对支持集稀疏性极其鲁棒。这反过来解释了为什么之前"支持集去污染"（Ring 3 的边界腐蚀、Phase 3 的正交投影）收益都很小——**支持集这一侧本来就不是瓶颈**。
2. **`Rough-Box` 的 1.44pp 恢复说明"盒外背景参照"是一个干净、零成本的信号**。如果要做弱标注方向，它适合作为 baseline 而不是主方法。
3. **chair / desk 的 box 掉分机制值得单独看**：这两类的 AABB 内部包含大量"桌下空间/椅子之间的空隙"，污染点与前景在几何上邻近但语义无关。这是"弱标注 + 空间邻近"的真实难点，但只影响 2/10 类。

### 5.3 建议

- **不建议**把"弱标注支持集"作为主攻方向。痛点是 1–2pp 级别，且可被朴素清洗大部分消解。
- 如果一定要做，切入口应该是 **chair / desk 这类"中空结构"的 box 污染**，而不是笼统的"弱标注"。
- 更值得投入的方向仍然是查询集侧：Ring 4 已经证明桥梁 B 无独立贡献，Phase 1 的超点一致性平滑是唯一稳定为正的组件（+2.93pp Arith）。弱标注的 1–2pp 量级和它相比不具备竞争力。
